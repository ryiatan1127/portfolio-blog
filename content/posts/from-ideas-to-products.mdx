我一直觉得，学习软件工程最有意思的地方，并不是学会某一种编程语言，而是当一个想法真正变成可以运行的东西时，你会突然意识到：

**原来一个想法真的可以被实现。**

从最初学习 C、Python，到后来接触人工智能，再到开始尝试 Agent、自动化和独立产品开发，我逐渐发现，自己真正感兴趣的并不是“把代码写出来”本身，而是：

> **Can I turn an idea into something that actually works?**

这也是我开始不断做项目的原因。

## 01 — From Learning to Building

刚开始学习计算机的时候，我和很多学生一样，从基础语法、数据结构和算法开始。

那时候，代码更多是一道题目的答案。

输入一个数字，输出一个结果；
实现一个排序算法；
完成一个课程设计。

但随着学习深入，我开始觉得，仅仅完成题目是不够的。

我开始尝试问自己：

**如果不再有题目告诉我应该做什么，我还能做出什么？**

于是，我开始参加人工智能相关比赛，也开始尝试把课堂上学到的知识应用到真实的问题中。

在这个过程中，我逐渐从“学习技术”转向了“使用技术创造东西”。

这也是我后来不断做独立项目的起点。

## 02 — Exploring AI Beyond the Classroom

人工智能是我大学阶段非常感兴趣的方向。

我参加过多次人工智能相关比赛，并获得了一些奖项。但比比赛结果更重要的是，这些经历让我开始思考：

**AI 到底应该怎样真正进入软件？**

如果 AI 只是一个聊天窗口，它能够回答问题。

但如果把 AI 放进一个完整的软件系统里，让它能够理解任务、调用工具、操作环境，并最终完成一个目标，它就不再只是一个“聊天机器人”。

它更像是一个能够参与生产过程的 Agent。

于是，我开始尝试自己的 Agent 项目。

## 03 — Teaching an Agent to Build 2D Games

其中一个比较有趣的项目，是一个用于**批量制作 2D 游戏的 Agent**。

最开始，我只是想验证一个很简单的想法：

> 如果一个人可以通过代码制作游戏，那么 AI 是否也可以参与这个过程？

但真正开始实现之后，我发现问题远比“让 AI 写代码”复杂。

一个游戏并不是一段代码。

它包含：

* 游戏逻辑
* 场景
* 角色
* UI
* 素材
* 交互
* 参数配置
* 测试
* Debug

因此，我开始尝试把游戏制作过程拆解成不同的步骤，再让 Agent 按照一定的流程完成任务。

这个项目让我第一次比较完整地接触到了一个重要的问题：

**如何把一个开放式目标，转换成机器可以执行的工作流。**

这对我后来理解 Agent architecture 有很大的帮助。

## 04 — Making Automation Feel More Human

另一个项目是我的**小红书自动化 Agent**。

它尝试将信息获取、内容处理、内容制作和发布连接起来，同时加入了类人的操作方式。

这个项目让我意识到：

**Automation is not simply about making a computer click faster.**

真正困难的地方，是如何让一个自动化系统在面对真实网页环境时依然具有一定的鲁棒性。

真实世界的网页并不像 API 一样稳定。

页面可能发生变化；
元素的位置可能变化；
操作流程可能变化；
某些步骤还需要根据当前状态做判断。

因此，在这个项目里，我开始更加关注：

* Browser Automation
* Web Interaction
* Workflow Design
* State Management
* Error Handling
* Human-like Interaction

这也是我第一次真正感受到：

> **软件工程的难点，往往不在“让它跑起来”，而在“让它稳定地跑下去”。**

## 05 — Building Software for Real Problems

除了 AI 项目，我也一直在尝试做一些更加传统的软件产品。

例如，我开发了一个**多平台 CRM 聚合软件**。

它的核心想法很简单：

现在很多团队同时使用 Telegram、WhatsApp 等不同通信平台。

如果所有消息、联系人和账号都分散在不同的平台里，管理起来会非常低效。

所以我尝试把不同平台的信息整合到一个系统中，并支持多账号、多平台的统一管理。

这个项目让我开始从另外一个角度理解软件开发：

**技术不是最终目的。**

一个软件真正有价值的地方，是它解决了一个真实的问题。

这也是我逐渐开始从“Developer”向“Builder”转变的过程。

## 06 — Software Can Also Be Creative

我并不希望自己的项目全部都是工具。

所以后来，我又做了一个名为 **PRISON** 的文字类拖拽解密游戏。

与 CRM 和 Agent 不同，这一次我关注的是：

**How can software create an experience?**

我开始思考游戏的交互、谜题、文字、视觉反馈，以及玩家和系统之间的关系。

这让我意识到，软件工程并不只是逻辑和代码。

它同样可以承载：

* Storytelling
* Interaction
* Design
* Creativity

对我来说，这也是计算机最吸引我的地方之一。

它既可以是一门严谨的工程学科，也可以成为表达创意的工具。

## 07 — ORDO: A Small Product With a Big Lesson

我还开发了一个轻量化记账软件 **ORDO**。

相比一些大型项目，ORDO 反而让我更加关注产品设计本身。

一个好的软件不应该要求用户学习如何使用它。

它应该尽可能自然。

因此，在设计 ORDO 的时候，我开始关注：

**What does the user actually need?**

而不是：

**What features can I add?**

这两个问题看起来很接近，但实际上完全不同。

前者关注用户。

后者关注开发者。

而做 ORDO 的过程让我越来越意识到：

> **Good software is not about having more features. It is about making the right things easier.**

## 08 — What I Am Really Trying to Build

回头看这些项目，它们表面上并不完全相同。

有 AI Agent。

有自动化工具。

有 CRM。

有游戏。

有记账软件。

甚至还有一个记录个人成长的博客。

但它们背后其实有一条非常清晰的线：

**I like turning ideas into things that people can actually interact with.**

我喜欢从一个模糊的想法开始。

然后去学习自己还不会的技术。

把问题拆开。

不断试错。

最后让它真正运行起来。

这可能也是我选择软件工程的原因。

因为软件工程对我来说，从来不只是“写代码”。

它是一种把想法变成现实的方法。

## 09 — Looking Beyond Code

大学阶段，我也一直在尝试让自己接触更大的世界。

我参加过 Harvard Summit，也参加过学生实习生项目。

在英语学习和国际交流方面，我曾获得大嘴英语全国一等奖，以及“21世纪杯”英语演讲比赛浙江省一等奖。

这些经历让我逐渐意识到：

**技术能力和国际交流能力并不是两个互相独立的方向。**

一个真正有创造力的工程师，需要能够理解技术，也需要能够理解不同的人、不同的文化和不同的问题。

这也是我希望继续寻找国际交流机会的原因。

我希望能够把自己放到一个新的环境里。

认识来自不同国家和背景的人。

学习不同的思维方式。

同时，也把自己过去积累的技术和创造力带到那里。

## 10 — Keep Building

现在的我依然是一名软件工程学生。

我还有很多东西不会。

很多项目也远远没有达到真正成熟的程度。

但我越来越确定一件事情：

**I want to keep building.**

继续学习 AI。

继续研究 Agent。

继续做软件。

继续尝试游戏和产品。

继续记录自己的成长。

也继续走出熟悉的环境，看看技术和自己还能走多远。

因为对我来说，大学并不是为了最终得到一个“完成”的答案。

它更像是一段不断尝试的过程。

而我的答案，也许就藏在下一个还没有被实现的想法里。
